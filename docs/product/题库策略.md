# AceExam 题库策略（M5：课程归一对齐 + 题库飞轮）

> **状态**：Draft（2026-08-08，用户讨论后沉淀）
> **背景**：每个学校课程不同（公共课 ~50 门 / 专业基础课 ~2000 门 / 专业特色课数万门），人工建题库不可能覆盖长尾。本策略回答「题库怎么长大、怎么对齐、怎么保质量」。

## 一、问题拆解：课程长尾分三层

| 层级 | 例子 | 数量级 | 题库策略 |
|---|---|---|---|
| 公共课 | 高数、英语、线代、大物、马原 | ~50 门 | 官方/自建为主，AI 补全 |
| 专业基础课 | 数据结构、电路、会计学原理 | ~2000 门 | 自建 + AI 生成 + UGC |
| 专业特色课 | 某校自创课、校本教材课 | 数万门 | 几乎全靠 UGC + OCR 录题 |

**核心洞察**：最后一层不可能人工建题库 → 这正是「拍照录题 OCR」五件套存在的意义：**让每个学生把课后题/往年卷拍进来，题库就长出来了**。

## 二、核心设计：课程三级归一对齐

「XX大学 2026 春《高等数学A》」和「YY大学《高等数学（上）》」是同一门课，但名字、教材、章节全不同。若每校独立题库 → 碎片化不可用。

解法是**三级对齐模型**：

```
课程实例（学校特有）         课程模板（归一）          知识点（对齐）
┌─────────────┐           ┌─────────────┐         ┌─────────────┐
│ 清华·高数A   │──┐        │             │         │ 函数与极限   │
│ 北大·高数上  │──┼───────►│ 高等数学     │────────►│ 导数与微分   │
│ 某职校·高数  │──┘        │  (code: ma) │         │ 积分学       │
└─────────────┘           └─────────────┘         └─────────────┘
    user_subjects             subjects               kp_tree
```

- **用户侧**：选「本校课程实例」→ 系统自动**映射到模板课程**（AI 做课程名匹配 + 教材版本识别）
- **题库侧**：题目挂在**模板课程 + 知识点**上，不挂在某校实例
- **效果**：清华学生传的题，北大/职校学生都能刷到；同一知识点跨校共享，题库规模放大 100 倍

### 数据模型增量（M5）

| 表/字段 | 说明 |
|---|---|
| `course_aliases`（新表） | 同课多名映射：alias（如"高等数学A"/"高数上"）→ template_subject_id |
| `user_subjects.template_subject_id` | 用户所选课程实例映射到的模板课程外键 |
| `subjects.level`（新字段） | 'public'（公共课）/ 'major'（专业基础课）/ 'school'（校本特色课） |
| `questions.source` | 已有：textbook / past_exam / self_built / ugc（M3.5 已落地 UGC） |
| `questions.status` | 已有审核流：draft→pending→active/rejected |

## 三、题库「四源 + 飞轮」

```
                    ┌─ 官方题库（教材/真题，自建）—— 种子
                    ├─ AI 批量生成（DeepSeek 按知识点出题）—— 数量
                    ├─ UGC 拍照录题（OCR，学生上传）—— 长尾
                    └─ 学生错题反哺（行为数据 → 标记易错点）—— 质量
```

每道题过**质量漏斗**：

```
AI生成/UGC上传 ──► AI初审（自动校验答案/题干完整性）
              ──► 用户互审（同校同学投票 + 纠错）   ← 校园社交属性
              ──► 行为反馈（正确率<40% = 有争议，标记复核）
              ──► active（进题库）
```

现有 `questions` 字段全支持（source / status / submitted_by / reviewed_by / reject_reason）。**缺 AI 初审自动化** → 可作为 M5 的 ep-ai 任务。

## 四、AI 生成质量保证（RAG 喂料 + 双向校验）

纯 DeepSeek 生成量大但错误率可观（尤其高数）。方案：

1. **教材上传**（已有 `textbook_uploads` + RAG 管线）→ 向量化分块
2. AI 生成题目**强制引用教材分块**（ADR-0003 citation 溯源机制）——无引用来源的题标 pending 不直接进题库
3. **答案可验证题**（选择/填空）用规则引擎抽检：AI 自算 + 反向代入验证
4. 正确率<40% 降权，>80% 且刷题量大标记「精品」——**质量用数据长出来**

## 五、落地优先级

| 阶段 | 做什么 | 对应现有资产 |
|---|---|---|
| **M5** | `course_aliases` 课程归一对齐 + `subjects.level` + 广场按模板课展示 | subjects.is_public 已埋 |
| **M5** | UGC 传题 + **AI 初审管线**（OCR 已通，加审核流自动化） | source='ugc' 已埋 |
| **M6** | AI 按知识点批量生成 + 引用校验 | RAG citation 已埋 |
| **长期** | 校园版（同校排行榜/互审）—— 社交裂变点 | classes 表已存在 |

## 六、总结

「每个学校课程不同」不是 bug 是 feature——课程碎片化让 UGC+OCR 门槛效应成为壁垒。**目标不是把题库做完，而是搭一个让题库自己长大的机制**：课程归一（共享放大）+ 四源供题（规模）+ 质量漏斗（信任）。
