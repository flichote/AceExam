# ADR-0003：RAG 引用溯源为硬约束 —— AI 讲解必须可溯源，禁止凭空编造

- **状态**：Accepted（M1 基线，硬性约束）
- **日期**：2026-08-07
- **决策者**：ep-arch（评审：ep-ai / ep-qa）

## 背景（Context）

教育场景的 AI 讲解一旦出现编造（幻觉），轻则误导学生、重则毁掉产品信任。竞品搜题 App"只给答案不讲透"，AceExam 的差异化正是"基于用户教材、可溯源的 step-by-step 讲解"（PRD §1.2/§2 ④讲解）。项目硬性约束：**AI 讲解必须 RAG 溯源（引用教材片段），禁止凭空编造**。

## 决策（Decision）

1. **AI 讲解一律走 RAG 管线**（architecture.md §3）：文档切块 → embedding → pgvector 检索 → 上下文组装 → DeepSeek 生成。
2. **结构化引用输出**：讲解响应必须带 `citations: [{source, chapter, section, page, snippet}]`，前端 CitationBlock 渲染；`uncovered` 标志标识无命中。
3. **无命中兜底**：检索相似度 < 阈值（0.75）→ `uncovered: true`，前端明确提示"教材未覆盖该知识点"，给通用讲解但**不伪装引用**。
4. **Prompt 约束**：rag_engine 的 system prompt 明确"只依据引用内容讲解，未覆盖部分明说不知道"，从生成端抑制幻觉。
5. **质量门禁**：ep-qa 提供 RAG 质量评估（引用是否真实存在于语料、讲解是否基于引用），纳入 pytest 烟测。

## 备选方案（Considered）

- **纯模型讲解（无 RAG）**：快但不可溯源，违反硬性约束，否决。
- **RAG 但引用可宽松**：检索不到也"编"个引用位置，产品信任崩塌，否决。
- **只给讲解不给引用**：用户无法验证，且"基于我的教材"卖点落空，否决。

## 后果（Consequences）

- **正面**：信任壁垒（可验证、可溯源）；与搜题 App 形成体验区隔；用户上传教材成为内容资产。
- **代价/风险**：管线复杂度上升（切块/embedding/检索质量都要调）；无命中场景体验打折（需引导上传教材）；检索质量差时讲解空洞 —— 由质量门禁与阈值调优兜底。

## 验收标准（Verification）

- [ ] 讲解响应 JSON 恒含 `citations` 字段（可为空数组 + `uncovered=true`）
- [ ] 引用片段与语料原文一致（ep-qa 抽查脚本）
- [ ] 无命中场景前端显示"教材未覆盖"提示，且无虚假引用
